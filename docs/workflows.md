## 三个有区别的分工示例

说明：以下均为分工方法示例，不是自动任务调度、不做百分比计量，也不表示任何已验证的运行结果或性能数据。CLI 文本模式由 Codex 把最小必要内容嵌入提示词；MCP 智能体模式可读写明确提供的 scratch 文件，并请求 Codex 调用任务名单中的插件。两种方式都不授予任意工作区或插件账户访问权限。

### A. 1000 行合成产品资料清洗和分类

- **输入**：Codex 校验 CSV 结构，提取 1000 行的 ID/name/category，先做 30–50 行小样。把规则和小样文本写入 `--prompt-file`。
- **DeepSeek 交付**：严格 JSON：清洗后的 rows 与 issues（未知类别、缺失名称），保留原 ID 和顺序。
- **Codex 交付**：输入校验、分批调用预算、合并结果、按 ID/顺序/类别映射/缺失规则验收，并保留源行号。
- **验收**：行数、ID 顺序、Title Case、非 ASCII 不翻译、issues 与规则一致；不以自造 ok 字段通过。
- **不适用/偏离约半**：若数据需本地脚本可稳定完成、或涉及不可外发的客户数据，则不应调用模型；双方工作量接近 50/50 只是大批量时的粗估，不精确测量。

### B. 公共长文档 12 章节提炼证据

- **输入**：Codex 确认文档可外发，按章节切分，把章节文本与固定证据字段嵌入提示词；保留章节 ID。
- **DeepSeek 交付**：每章返回引用句、章节 ID、简短归纳与不确定性标记，只基于给定文本，不补充外部事实。
- **Codex 交付**：校验章节覆盖、来源行/章节 ID 可回溯、超长截断策略、结构化合并与人工抽查清单。
- **验收**：12 章均有输出；引用句能在原文定位；不得声称联网或补充文档外事实。
- **不适用/偏离约半**：若只需规则抽取或文档不可外发，则不适用；双方接近各半因 DeepSeek 产出证据草稿，Codex 负责切分、校验与整合。

### C. 开源小模块改造

- **输入**：Codex 先确认代码可外发并给出接口约束、失败场景和最小上下文，整理成提示词。
- **DeepSeek 交付**：候选实现补丁草稿与测试数据/用例建议，标注假设，不声称已运行或发现真实 bug。
- **Codex 交付**：应用补丁、构建与测试、静态审查、边界条件补齐，决定是否合并。
- **验收**：测试通过、接口不变或变更已记录、无敏感信息外泄；保留来源文件/行号。
- **不适用/偏离约半**：若代码不可外发或改动极小，应本地处理；接近各半是因为 DeepSeek 给出候选实现与测试素材，Codex 承担应用与验证。
