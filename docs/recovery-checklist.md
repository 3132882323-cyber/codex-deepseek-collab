# GPT 与 Flash 恢复检查清单

下文循环和时间数字是旧模式。[长任务模式](long-tasks.md)取消这些累计配额、增大阶段额度和超时，并新增 time_slice；错误分类、取消、哈希验收和工具去重原则相同。

本表是操作参考，不是某次故障或实测记录。GPT 保持主对话，Flash 使用首次明确规划的思考强度和生成预算；不因失败自动扩容或切到 Pro。长任务优先拆成可验收的小文件批次。

CLI/MCP 的 `retry_transient_transport` 通用缺省为 `false`，仅在使用者明确授权后启用。网络重试与 HTTP 重试合计最多 3 次尝试，计入退避和任务剩余期限，并尊重 `Retry-After`。

| 错误类别 | 重试或续跑行为 | 主控检查 |
| --- | --- | --- |
| 白名单临时 socket、连接错误或本地请求超时 | 显式启用后有限重试 | 核对脱敏错误短码、尝试数和剩余时间 |
| HTTP 429/500/502/503/504 | 按既有策略有限重试 | 核对 `Retry-After`，不超共享额度 |
| 未知、TLS 或 DNS 错误 | 不自动重放 | 保留脱敏诊断，核实配置和网络 |
| 认证、模型、参数错误或最终答案为空 | 停止 | 校验配置和完整输出，不切换模型 |
| HTTP 200 的坏 JSON、干净但不完整的 SSE、实际输出截断 | 不自动重放或扩容 | 检查结束原因、已写产物和测试证据 |
| 步骤或工具额度用尽 | `paused`，保留已验证产物与未执行批次 | 按预定计划，以同一任务 ID 和进程追加必要额度 |

每次请求最多 180 秒，每个模型步骤的请求及退避最多 360 秒，并受任务剩余期限约束。续跑每次最多追加 12 步、24 工具及必要的 360000 ms；累计硬限为 48 步、96 工具、144 HTTP、从首次开始 30 分钟。主控可事先规划最多两个恢复阶段，不在外层反复创建替代任务。

仅未过期的同进程暂停任务能继续。真正的 `failed/cancelled/completed`、旧版本已清理历史的失败任务或 MCP 重启后的任务不能复活；文件本身仍须按内容与 SHA-256 独立验收。

已完成的本地文件操作和已回传的插件结果不重新派发。网络重试前提供商可能已经处理或计费，不能据此保证上游恰好执行一次。取消会停止本地等待和后续操作，不能撤销上游工作。HTTP 200 或已有部分文件都不等于任务完成，主控须核对完整交付和实际测试证据。

详细参数见[可靠性说明](reliability.md)和[续跑接口](../skills/deepseek-collaboration/references/agents.md)。
